# AI 작업실 실행기 (ai-desk)

노션 **AI 작업실 › 요청함**에 들어온 지시서를 Coral Bricks·Hive로 처리하고, 결과를 노션에 남기는 작은 Cloudflare Worker입니다.
기존 입찰 서버(`g2b-mcp`)와는 완전히 분리되어 있고, 그 서버를 건드리지 않습니다.

```
나 / Claude / ChatGPT ──지시서──▶ ① 노션 요청함 (상태=대기)   ─┐
                                 ② 입력창 (지금 실행)          ─┤
                                                               ▼
                              실행기 (1분마다 요청함 확인, 또는 입력창 요청 즉시)
                                ├─ 지시서·[참고] 페이지 읽기 (1단계)
                                ├─ 자체조사: 노션 검색·읽기 최대 N회 (2단계, 체크했을 때만)
                                ├─ Coral / Hive LLM / Hive 검사 호출
                                └─ 결과를 행 아래에 덧붙이기 또는 작업 기록에 새 페이지 → 다시 읽어 확인
```

## 무료 한도 판단

Cloudflare Workers 무료 플랜 기준([한도 문서](https://developers.cloudflare.com/workers/platform/limits)):

| 한도 | 무료 플랜 | 이 실행기 |
|---|---|---|
| 실행 1회당 외부 호출 | 50회 | 45회에서 멈추고, 저장용 10회를 남겨 둠. 1회에 요청 1건만 처리 |
| 실행 1회당 계산 시간 | 10ms (응답 대기 시간 제외) | 대부분 응답 대기라 여유 있음. 실제 운영에서 로그로 확인 필요 |
| 주기 실행 1회 길이 | 15분 | 모델 응답을 기다려도 충분 |
| 주기 실행 개수 | 계정당 5개 | 1개 사용. 기존 Worker들이 쓰는 개수와 합쳐 5개 이하인지 확인 |
| 하루 요청 | 100,000회 | 1분 주기 = 하루 1,440회 |

계산 시간 초과가 실제로 자주 나면(로그에 `exceeded CPU`), 다른 실행 채널(GitHub Actions 등)로 옮기는 것을 검토합니다.

## 설정 순서 (본인이 직접 하는 일)

비밀값은 **채팅이나 노션에 붙여넣지 말고**, 아래에서 말하는 Cloudflare 화면에만 넣습니다.

1. **노션 실행기 연결 만들기**
   - <https://www.notion.so/profile/integrations> → 새 연결(내부) → 이름 `AI 작업실 실행기`, 워크스페이스 선택
   - 기능: 콘텐츠 읽기·콘텐츠 업데이트·콘텐츠 삽입만 켜고, 댓글·사용자 정보는 끕니다
   - 만들어진 비밀 토큰은 4번에서 `NOTION_TOKEN`으로 넣습니다
   - 노션 **AI 작업실** 페이지 → 오른쪽 위 `•••` → 연결 → `AI 작업실 실행기` 추가 (하위 요청함·작업 기록에 같이 적용)
   - 실행기가 읽어야 하는 다른 자료(예: 입찰 연구 페이지)도 같은 방법으로 연결합니다. **연결한 페이지만** 읽고 검색할 수 있습니다
2. **Coral Bricks 키**: 콘솔 → API Keys → 새 키. 조직 설정에서 데이터 미보관(zero data retention) 옵션이 있으면 켭니다
3. **Hive 키**: Hive 계정에서 V3 API 키를 만듭니다
4. **Cloudflare에 올리기** (기존 입찰 서버와 같은 계정)
   - Workers & Pages → Create → Import a repository → 이 GitHub 저장소 선택
   - Root directory: `ai-desk`, 배포 명령은 기본값(`npx wrangler deploy`)
   - 배포 후 이 Worker → Settings → Variables and Secrets → **Secret**으로 4개 추가
     - `NOTION_TOKEN`, `CORAL_API_KEY`, `HIVE_API_KEY`
     - `WEB_PASSCODE`: 입력창 암호. 비밀번호 관리자로 만든 **16자 이상** 무작위 문자열
5. **점검**
   - `https://ai-desk.<내 서브도메인>.workers.dev/health` → `secrets`와 `settings`가 모두 `true`인지 확인 (값 자체는 보이지 않음)
   - 입력창(`https://ai-desk.<내 서브도메인>.workers.dev/`) → 암호 입력 → **Coral 모델 목록 확인** → 실제 모델 ID 확인
   - 기본 모델 ID가 목록에 없으면 `wrangler.toml`의 `CORAL_MODEL`을 바꾸거나, 요청 행의 `모델` 칸에 적습니다
   - 짧은 시험 요청 1건 → 요청함 행이 `완료`가 되고 본문 아래에 결과가 붙는지 확인

## 보안과 데이터

- **외부 전송**: 지시서와 실행기가 읽은 노션 내용은 Coral Bricks(Coral·기본) 또는 Hive로 갑니다. 비밀값은 각 서비스로만 가고 노션·로그·화면에 남지 않습니다
- **노션 접근 범위**: 실행기 연결을 추가한 페이지와 그 하위만 접근할 수 있습니다
- **기존 자료 보존**: 실행기는 새 페이지 만들기, 블록 아래에 덧붙이기, 요청 행 속성 바꾸기만 합니다. 기존 블록 수정·삭제 호출은 코드에 없습니다(시험으로 확인)
- **저장 확인**: 작업 기록 페이지는 다시 읽어 보낸 내용과 비교하고, 요청 행 덧붙이기는 노션이 돌려준 저장 결과와 비교합니다. 다르면 상태가 `저장 확인 실패`가 됩니다
- **복구**: 실패한 요청은 오류 칸을 확인한 뒤 상태를 `대기`로 바꾸면 다시 실행됩니다. 20분 넘게 `실행 중`이면 자동으로 다시 시도하고, 3번 연속 멈추면 `실패`로 남깁니다. 노션 페이지 기록(버전 기록)으로 되돌릴 수도 있습니다
- **입력창**: 암호(16자 이상)가 없거나 틀리면 아무것도 만들지 않습니다. 암호가 유출됐다고 생각되면 `WEB_PASSCODE`를 바꿉니다

## 확인하지 못한 것 (첫 시험에서 확인)

- Coral 기본 모델 ID `deepseek-v4.1-flash-fast`: 공개 자료 기준이며, 계정에서 쓸 수 있는지는 모델 목록으로 확인
- Hive LLM 인증 방식(`Authorization: Bearer`)과 기본 모델 `zai-org/glm-5.3-flash`: Hive 문서 기준이며 첫 호출로 확인
- **Hive 검사**(AI 생성 글 감지 등)의 V3 요청 형식: 이 환경에서 Hive 문서를 직접 열 수 없어 확인하지 못했습니다. 그래서 `HIVE_CHECK_URL`과 `HIVE_CHECK_BODY`(예: `{"input":[{"text":"{{TEXT}}"}]}` 형태의 틀)를 문서 확인 후 채우도록 비워 두었습니다. 비어 있으면 Hive 검사 요청은 안내 문구와 함께 `실패`가 됩니다

## 개발

```bash
cd ai-desk
npm ci
npm run check    # 타입 검사 + 시험 (가짜 노션·Coral·Hive 사용, 실제 호출 없음)
```
